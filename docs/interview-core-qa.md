# 前端、后端与计算机网络面试核心题库

> 用途：面试前系统复习与口头背诵。回答先给结论，再讲原理，最后补充实践或取舍。

## 背诵方法

1. 第一遍只背每题第一句，建立知识框架。
2. 第二遍补充关键词、执行流程和典型场景。
3. 第三遍脱稿回答，并主动补充一个例子或一次排障经历。
4. 面试时控制在 30～90 秒：结论 → 原理 → 场景 → 取舍。

## 一、前端核心知识

### 1. HTML、CSS 与页面基础

#### 1. 什么是语义化 HTML？有什么好处？

**回答：** 语义化是用符合内容含义的标签组织页面，例如 `header`、`nav`、`main`、`article`、`button`。它能提升可访问性、SEO、代码可读性和浏览器默认行为的正确性。语义化不等于完全不用 `div`，而是在有明确语义时优先使用对应标签。

#### 2. `defer` 和 `async` 有什么区别？

**回答：** 两者都会并行下载脚本。`async` 下载完成后立即执行，执行顺序不确定，可能阻塞 HTML 解析；`defer` 等 HTML 解析完成后按文档顺序执行，并且早于 `DOMContentLoaded`。有依赖顺序的业务脚本通常使用 `defer`，独立统计脚本适合 `async`。

#### 3. CSS 盒模型是什么？

**回答：** 盒模型由 `content`、`padding`、`border`、`margin` 组成。默认 `content-box` 的宽高只计算内容区；`border-box` 的宽高包含内容、内边距和边框，布局更直观，因此工程中常全局设置 `box-sizing: border-box`。

#### 4. CSS 选择器优先级如何计算？

**回答：** 通常比较内联样式、ID、类/属性/伪类、元素/伪元素的数量，按从高到低逐级比较；同优先级后声明的生效。`!important` 会提高声明优先级，但应少用。继承值的优先级低于直接命中的规则。

#### 5. 什么是 BFC？能解决什么问题？

**回答：** BFC 是块级格式化上下文，是一个独立布局区域。它可以包含内部浮动、阻止外部浮动影响、避免相邻块垂直外边距折叠。常通过 `display: flow-root` 创建，旧方案还包括 `overflow: hidden/auto`。

#### 6. `display: none`、`visibility: hidden`、`opacity: 0` 的区别？

**回答：** `display: none` 不占布局空间，通常也不进入可访问树；`visibility: hidden` 占空间但不可见，不能交互；`opacity: 0` 仍占空间且默认仍可点击、可聚焦。隐藏交互元素时还要考虑 `pointer-events`、焦点和无障碍属性。

#### 7. Flex 与 Grid 如何选择？

**回答：** Flex 更适合一维布局，即沿主轴排列和分配空间；Grid 更适合同时控制行列的二维布局。组件内部排列常用 Flex，整体页面或规则网格常用 Grid，两者可以组合。

#### 8. 如何实现水平垂直居中？

**回答：** 首选 Flex 或 Grid，例如父元素设置 `display: grid; place-items: center`。绝对定位场景可用 `top: 50%; left: 50%; transform: translate(-50%, -50%)`。选择方案时要看元素尺寸是否已知、是否脱离文档流。

#### 9. 响应式设计的核心是什么？

**回答：** 核心是让布局、字号、图片和交互随可用空间变化，而不是针对每台设备写固定尺寸。常用流式布局、媒体查询、容器查询、相对单位、响应式图片和移动端优先策略。

#### 10. 重排和重绘有什么区别？

**回答：** 重排是浏览器重新计算元素几何信息，通常会连带重绘；重绘只更新像素外观，不改变布局。频繁读取布局属性并立即写样式会导致布局抖动。优化方式是批量读写、使用 `requestAnimationFrame`，动画尽量改变 `transform` 和 `opacity`。

### 2. JavaScript 核心

#### 11. JavaScript 有哪些基本数据类型？

**回答：** 基本类型有 `undefined`、`null`、`boolean`、`number`、`bigint`、`string`、`symbol`；对象属于引用类型。基本类型按值使用，对象变量保存的是引用值。`typeof null` 返回 `object` 是历史遗留问题。

#### 12. `==` 和 `===` 有什么区别？

**回答：** `===` 不进行隐式类型转换，类型和值都相同才为真；`==` 会按规则转换类型，容易产生难以预期的结果。业务代码通常使用严格相等，只有明确需要兼容 `null` 与 `undefined` 等场景时才谨慎使用宽松相等。

#### 13. `var`、`let`、`const` 的区别？

**回答：** `var` 是函数作用域，存在变量提升且可重复声明；`let` 和 `const` 是块级作用域，在声明前处于暂时性死区。`const` 禁止重新绑定，但不会让对象内部不可变。默认用 `const`，需要重新赋值时用 `let`。

#### 14. 什么是作用域链和闭包？

**回答：** 函数查找变量时会从当前词法作用域逐级向外查找，这就是作用域链。闭包是函数与其声明时词法环境的组合，即使外层函数已经返回，内部函数仍可访问外层变量。闭包常用于封装状态、回调和函数工厂，也可能因长期持有引用导致内存无法释放。

#### 15. `this` 的指向规则是什么？

**回答：** 普通函数的 `this` 由调用方式决定：默认调用、对象方法调用、`call/apply/bind` 显式绑定、`new` 构造调用，通常 `new` 优先级最高。箭头函数没有自己的 `this`，它捕获外层词法作用域的 `this`。

#### 16. 原型和原型链是什么？

**回答：** 每个普通对象都可以通过内部原型关联另一个对象。访问自身不存在的属性时，会沿原型向上查找，直到 `null`，形成原型链。JavaScript 的继承本质基于原型委托，`class` 是更易读的语法封装。

#### 17. `new` 操作符做了什么？

**回答：** `new` 会创建一个新对象，把它的原型指向构造函数的 `prototype`，以新对象作为 `this` 执行构造函数，最后在构造函数没有显式返回对象时返回新对象。

#### 18. 浅拷贝和深拷贝的区别？

**回答：** 浅拷贝只复制第一层属性，嵌套对象仍共享引用；深拷贝会递归复制整个对象图。展开运算符和 `Object.assign` 属于浅拷贝。现代浏览器可用 `structuredClone` 处理多数结构，但函数、DOM 节点等不能直接克隆。

#### 19. 防抖和节流的区别？

**回答：** 防抖是在连续触发结束后只执行一次，适合搜索输入、窗口调整；节流是在一段时间内最多执行一次，适合滚动监听、拖拽上报。两者都用于控制高频事件，但保留事件的时机不同。

#### 20. Promise 有哪些状态？如何变化？

**回答：** Promise 有 `pending`、`fulfilled`、`rejected` 三种状态，只能从等待态单向变为成功或失败，且状态不可逆。`then`、`catch`、`finally` 都返回新 Promise，因此可以链式组合和统一传递错误。

#### 21. `async/await` 的本质是什么？

**回答：** `async` 函数总是返回 Promise，`await` 是基于 Promise 的语法糖，会暂停当前异步函数的后续逻辑，但不会阻塞主线程。串行无依赖任务应使用 `Promise.all` 并发，否则连续 `await` 会增加总耗时。

#### 22. Event Loop 如何工作？

**回答：** JavaScript 主线程执行完当前同步任务后，会先清空微任务队列，再进入下一个宏任务，浏览器会在合适时机渲染。Promise 回调、`queueMicrotask` 属于微任务；定时器、网络事件回调通常属于宏任务。微任务持续产生可能阻塞渲染。

#### 23. `Promise.all`、`allSettled`、`race`、`any` 的区别？

**回答：** `all` 全部成功才成功，任一失败立即失败；`allSettled` 等待全部结束并返回每项结果；`race` 采用最先落定的结果；`any` 采用最先成功的结果，全部失败才失败。

#### 24. ES Module 与 CommonJS 的区别？

**回答：** ES Module 使用 `import/export`，依赖关系可静态分析，支持 Tree Shaking，浏览器原生支持；CommonJS 使用 `require/module.exports`，主要是 Node.js 的传统模块系统，通常运行时加载。两者在加载时机、默认导出和循环依赖行为上不同。

#### 25. 垃圾回收的基本原理是什么？

**回答：** 现代 JavaScript 引擎主要从根对象出发标记所有可达对象，再清理不可达对象，即标记清除。常见泄漏来源有未移除的事件监听器、定时器、闭包、全局缓存和脱离 DOM 的节点。

#### 26. Map 与 Object、Set 与 Array 如何选择？

**回答：** `Map` 支持任意类型键、顺序稳定、增删查语义清晰，适合动态键值集合；`Object` 更适合固定结构的数据记录。`Set` 保证值唯一且判断是否存在更直接；数组适合有序、可重复、需要索引的数据。

#### 27. TypeScript 的价值是什么？

**回答：** TypeScript 通过静态类型在编译期发现错误，并增强重构、自动补全和接口约束能力。它不会替代运行时校验，因为外部输入在运行时仍不可信。类型应服务于业务模型，避免滥用 `any` 和过度复杂的类型技巧。

#### 28. `interface` 和 `type` 有什么区别？

**回答：** 两者都能描述对象类型。`interface` 支持声明合并，常用于可扩展对象和类契约；`type` 能表达联合、交叉、元组、条件类型等更广泛结构。团队中应保持一致，优先选择表达最清晰的方式。

### 3. 浏览器与框架

#### 29. 浏览器从输入 URL 到页面显示经历了什么？

**回答：** 浏览器解析 URL，查询缓存和 DNS，建立 TCP 或 QUIC 连接，完成 TLS，发送 HTTP 请求；收到响应后解析 HTML 生成 DOM，解析 CSS 生成 CSSOM，合成渲染树，执行布局、绘制和合成，同时加载脚本、字体和图片。期间还可能发生重定向、Service Worker 拦截和缓存命中。

#### 30. 浏览器缓存有哪些？

**回答：** HTTP 缓存分强缓存和协商缓存。强缓存通过 `Cache-Control`、`Expires` 决定是否直接使用本地副本；协商缓存通过 `ETag/If-None-Match` 或 `Last-Modified/If-Modified-Since` 向服务器验证，未变化返回 `304`。指纹静态资源适合长期强缓存，HTML 通常需要及时验证。

#### 31. Cookie、localStorage、sessionStorage 的区别？

**回答：** Cookie 容量较小，会按规则随请求发送，可设置过期时间、作用域、`HttpOnly`、`Secure`、`SameSite`；`localStorage` 持久保存在同源下；`sessionStorage` 只在当前标签页会话内存在。Web Storage 同步读写且不能防 XSS，因此不应保存敏感凭证。

#### 32. DOM 事件流是什么？

**回答：** 事件依次经历捕获、到达目标、冒泡三个阶段。事件委托利用冒泡，把多个子元素的监听器合并到祖先元素上，适合动态列表并可降低监听器数量。要通过 `event.target` 或 `closest` 判断实际目标。

#### 33. 什么是虚拟 DOM？

**回答：** 虚拟 DOM 是对 UI 结构的 JavaScript 描述。状态变化后框架生成新描述，与旧描述比较，再把必要变更提交到真实 DOM。它的核心价值是提供声明式编程和跨平台抽象，并不意味着每种场景都比手写 DOM 更快。

#### 34. React 为什么需要 `key`？

**回答：** `key` 帮助 React 在同级列表中识别元素身份，决定复用、移动还是销毁节点。应使用稳定且唯一的业务 ID；使用数组下标可能在插入、删除或排序时导致状态错位和不必要渲染。

#### 35. React Hooks 为什么不能写在条件语句里？

**回答：** React 依赖 Hooks 每次渲染的调用顺序来关联状态。如果条件执行改变顺序，状态会绑定到错误位置。因此 Hooks 必须在组件或自定义 Hook 顶层调用。

#### 36. `useEffect` 的作用和常见问题是什么？

**回答：** `useEffect` 用于把组件与网络、订阅、计时器、DOM 等外部系统同步。依赖应完整，副作用需要时返回清理函数。不要用 Effect 计算可在渲染期间直接得到的派生状态，否则容易产生额外渲染和状态不同步。

#### 37. React 如何减少不必要渲染？

**回答：** 先缩小状态范围并拆分组件，再按实际性能数据使用 `memo`、`useMemo`、`useCallback`。保持引用稳定有助于避免子组件重复渲染，但无差别缓存会增加复杂度和内存成本，应通过 Profiler 定位热点。

#### 38. Vue 2 与 Vue 3 响应式原理有什么区别？

**回答：** Vue 2 主要使用 `Object.defineProperty` 劫持已有属性，因此新增、删除属性和部分数组变化需要特殊处理；Vue 3 主要使用 `Proxy` 代理对象，可统一拦截更多操作，并通过依赖收集和触发更新实现响应式。

#### 39. Vue 的 `computed` 和 `watch` 如何选择？

**回答：** `computed` 用于根据响应式数据声明式计算一个可缓存值；`watch` 用于数据变化后执行异步请求、日志、命令式操作等副作用。能用计算属性表达的派生数据，不应使用监听器重复维护。

#### 40. 单向数据流有什么好处？

**回答：** 状态通过明确路径向下传递，更新通过事件或动作向上表达，使数据变化可追踪、可预测、便于调试。跨层共享状态可用 Context、状态库或依赖注入，但不应把所有局部状态都提升成全局状态。

### 4. 工程化、性能与安全

#### 41. Webpack、Vite 等构建工具解决什么问题？

**回答：** 它们处理模块解析、代码转换、资源打包、开发服务器、热更新、代码分割和生产优化。Vite 开发阶段主要利用原生 ESM 按需提供模块，启动快；生产仍会进行优化构建。工具选择取决于生态、兼容性和项目规模。

#### 42. Tree Shaking 的前提是什么？

**回答：** Tree Shaking 依赖静态可分析的 ES Module，并需要构建器确认未使用导出且模块没有不可安全删除的副作用。库应正确配置模块入口和 `sideEffects`，动态引用或 CommonJS 会降低效果。

#### 43. 什么是代码分割和懒加载？

**回答：** 代码分割把一个大包拆成多个按需加载的块，懒加载在路由或功能真正需要时再下载对应代码。它能降低首屏体积，但块过碎会增加请求和调度开销，应结合路由、业务边界和预加载策略设计。

#### 44. 如何优化首屏性能？

**回答：** 先用真实指标定位，再减少关键路径资源：压缩和分割代码、内联关键 CSS、延迟非关键脚本、优化图片和字体、使用 CDN 与缓存、服务端渲染或静态生成。重点关注 LCP、INP、CLS，并区分实验室数据与真实用户数据。

#### 45. 图片如何优化？

**回答：** 选择合适尺寸和 WebP/AVIF 等格式，使用 `srcset/sizes` 响应式加载，非首屏图片懒加载，首屏关键图避免延迟并可提高请求优先级，同时设置宽高防止布局偏移。还要结合压缩、CDN 和缓存。

#### 46. 什么是 XSS？如何防御？

**回答：** XSS 是攻击者让恶意脚本在受害者浏览器中执行。核心防御是按输出上下文正确转义，避免把不可信内容插入 `innerHTML`，富文本使用可靠白名单清洗，并配置 CSP。Cookie 设置 `HttpOnly` 可降低凭证被脚本窃取的风险，但不能替代 XSS 修复。

#### 47. 什么是 CSRF？如何防御？

**回答：** CSRF 利用浏览器自动携带身份凭证，诱导已登录用户向目标站点发起非本人意愿的请求。可使用 `SameSite` Cookie、CSRF Token、校验 `Origin/Referer`，并确保修改操作不用 GET。若凭证只通过自定义请求头携带，风险也会降低。

#### 48. 什么是 CORS？

**回答：** CORS 是浏览器执行的跨源资源共享机制，服务器用响应头声明允许哪些源、方法和请求头。复杂请求会先发 OPTIONS 预检。CORS 不是服务器之间的安全边界，也不能阻止攻击者直接向后端发送请求。

#### 49. 前端如何做错误监控？

**回答：** 收集脚本异常、Promise 拒绝、资源加载失败、接口错误和性能指标，附带版本、页面、用户操作链路等上下文，通过 Source Map 还原源码位置，并做好采样、脱敏、聚合和告警。错误边界可以改善 React 局部故障体验，但不能捕获所有异步错误。

#### 50. SSR、SSG、CSR 的区别？

**回答：** CSR 在浏览器中渲染，交互灵活但首屏和 SEO 依赖优化；SSR 每次请求在服务端生成 HTML，首屏和 SEO 较好但服务器成本更高；SSG 在构建时生成静态页面，性能与稳定性好但内容更新需要重建。现代框架常按页面混合使用。

## 二、后端核心知识

### 1. API、架构与操作系统

#### 51. RESTful API 的核心原则是什么？

**回答：** REST 以资源为中心，用 URI 标识资源，用 HTTP 方法表达操作，并保持请求无状态。接口应正确使用状态码、统一错误结构，支持分页、过滤、版本演进和幂等性。REST 是设计风格，不是强制公式。

#### 52. GET、POST、PUT、PATCH、DELETE 有什么区别？

**回答：** GET 获取资源，应安全且幂等；POST 通常创建资源或执行非幂等操作；PUT 通常整体替换资源且幂等；PATCH 部分更新；DELETE 删除资源，语义上应幂等。具体实现要让文档、权限和实际副作用一致。

#### 53. 什么是幂等？如何实现？

**回答：** 幂等指同一操作执行一次或多次，最终业务效果一致。查询天然幂等，更新可用确定值覆盖；创建、支付等操作可通过幂等键、唯一约束、状态机和事务实现。幂等不代表每次返回内容完全相同。

#### 54. 分层架构有什么价值？

**回答：** 常见分层包括接口层、应用层、领域或业务层、数据访问层。分层能隔离变化、明确职责、提高可测试性，但层次过多会带来样板代码和调用链复杂度，应围绕业务边界而不是机械套模板。

#### 55. 进程、线程和协程有什么区别？

**回答：** 进程是资源隔离和分配单位，线程是操作系统调度的执行单位，同进程线程共享大部分内存；协程通常由用户态运行时调度，切换成本更低，适合大量 I/O 并发。协程不能自动提升 CPU 密集任务性能。

#### 56. 并发和并行有什么区别？

**回答：** 并发是多个任务在时间上交替推进，并行是多个任务在同一时刻真正执行。单核可以并发，多核才能实现 CPU 指令级的并行。I/O 密集型关注等待期间复用线程，CPU 密集型关注核数和任务拆分。

#### 57. 什么是用户态和内核态？

**回答：** 用户态权限受限，应用不能直接访问硬件和关键内存；内核态拥有高权限。应用通过系统调用进入内核完成文件、网络、进程等操作。切换有成本，因此高性能系统会减少不必要的系统调用和数据复制。

#### 58. 什么是上下文切换？

**回答：** CPU 从一个线程或进程切换到另一个时，需要保存和恢复寄存器、栈、调度状态等上下文，还可能影响缓存命中。线程过多、锁竞争或频繁阻塞会增加切换成本，因此并发量不是越大越好。

#### 59. 死锁产生的四个必要条件是什么？

**回答：** 互斥、请求并保持、不可剥夺、循环等待。破坏任一条件都能预防死锁，例如固定加锁顺序破坏循环等待，超时获取锁降低永久等待风险。排查时关注锁依赖图和线程栈。

#### 60. 同步、异步、阻塞、非阻塞如何区分？

**回答：** 同步与异步描述结果通知方式：调用者主动等待或查询，还是完成后被通知；阻塞与非阻塞描述调用期间线程是否被挂起。同步不一定阻塞，异步也不等于多线程。

#### 61. I/O 多路复用是什么？

**回答：** I/O 多路复用让一个线程监控多个文件描述符的就绪事件，就绪后再处理，避免为每个连接长期占用一个线程。Linux 常见 `select`、`poll`、`epoll`；`epoll` 更适合大量连接，避免每次线性扫描全部描述符。

### 2. 数据库与事务

#### 62. 数据库索引为什么能加速查询？

**回答：** 索引用额外空间维护有序结构，使查询从全表扫描变为更少的树查找和磁盘页访问。代价是占用空间，并增加插入、删除、更新成本。索引设计必须结合真实查询、选择性和排序需求。

#### 63. 为什么 MySQL 常用 B+ 树索引？

**回答：** B+ 树分支多、树高低，能减少磁盘 I/O；数据主要位于叶子节点，叶子节点有序相连，既适合等值查询也适合范围扫描。哈希索引等值查找快，但不擅长范围、排序和最左前缀查询。

#### 64. 聚簇索引和二级索引有什么区别？

**回答：** InnoDB 聚簇索引的叶子节点存整行数据，一张表只有一个，通常是主键；二级索引叶子节点存索引列和主键值。通过二级索引查询非覆盖列时，需要再按主键访问聚簇索引，称为回表。

#### 65. 什么是联合索引的最左前缀原则？

**回答：** 联合索引按列的定义顺序排序，查询通常需要从最左列开始连续利用索引。遇到某些范围条件后，后续列对缩小扫描范围的作用可能受限。设计时把高频过滤、等值条件、排序和选择性一起考虑，不能只背“高区分度放前面”。

#### 66. 哪些情况可能导致索引失效？

**回答：** 常见原因有对索引列做函数或隐式类型转换、无法满足最左前缀、前导模糊匹配、条件选择性太低、复杂 `OR` 等。是否使用索引最终由优化器基于成本决定，应通过执行计划验证。

#### 67. 什么是覆盖索引？

**回答：** 如果查询所需列都能直接从某个索引获得，就不必回表，这个索引对该查询就是覆盖索引。它可减少随机 I/O，但索引列过多会增加空间和写入成本。

#### 68. 如何分析慢 SQL？

**回答：** 先用慢查询日志和监控定位，再看执行计划中的访问类型、扫描行数、索引、排序和临时表；同时检查数据分布、锁等待、网络和连接池。优化可以从改 SQL、建合适索引、减少返回列、拆分批量操作、调整模型入手，并用真实数据验证。

#### 69. 事务的 ACID 是什么？

**回答：** 原子性保证事务全部成功或全部回滚；一致性保证约束在事务前后成立；隔离性控制并发事务相互影响；持久性保证提交结果不会因故障丢失。数据库通过日志、锁、MVCC 等机制共同实现。

#### 70. 事务隔离级别有哪些？

**回答：** 标准隔离级别为读未提交、读已提交、可重复读、串行化。级别越高，并发异常越少，但并发能力和成本通常更高。不同数据库的具体实现和默认级别不同，不能只根据名称推断行为。

#### 71. 脏读、不可重复读、幻读是什么？

**回答：** 脏读是读到其他事务未提交的数据；不可重复读是同一行前后读取结果不同；幻读是同一条件前后读取到的行集合变化。MVCC 和锁会根据隔离级别控制这些现象。

#### 72. MVCC 是什么？

**回答：** MVCC 通过保存数据的多个版本，让读操作基于一致性快照读取，从而减少读写互相阻塞。它通常依赖事务版本、Undo Log 和可见性规则。MVCC 不是完全无锁，写写冲突和当前读仍可能加锁。

#### 73. 乐观锁和悲观锁的区别？

**回答：** 悲观锁假设冲突频繁，操作前先锁定资源；乐观锁假设冲突较少，提交时用版本号或条件更新检测冲突。悲观锁简单但可能降低并发，乐观锁并发高但冲突时需要重试。

#### 74. 数据库主从复制有什么作用和问题？

**回答：** 主库记录变更日志，从库重放，实现读扩展、备份和故障切换。异步复制可能产生延迟，导致读到旧数据；故障切换还要处理数据丢失、脑裂和连接迁移。强一致读通常要访问主库或等待复制位点。

#### 75. 分库分表何时需要？

**回答：** 当单库的容量、吞吐或维护窗口成为明确瓶颈，且索引、SQL、缓存、读写分离等手段不足时再考虑。分片会引入路由、跨分片查询、分布式事务、全局 ID、扩容迁移等复杂度，分片键必须结合访问模式选择。

### 3. 缓存、消息队列与分布式系统

#### 76. Redis 为什么快？

**回答：** Redis 数据主要在内存中，核心命令执行路径短，数据结构针对场景优化，并使用事件驱动和 I/O 多路复用处理连接。新版本可用 I/O 线程辅助网络读写，但命令执行仍强调避免阻塞。

#### 77. Redis 常见数据结构及场景？

**回答：** String 用于缓存、计数、分布式锁基础值；Hash 存对象字段；List 用于队列或时间线；Set 用于去重、交并集；Sorted Set 用于排行榜和延迟任务；Bitmap、HyperLogLog、Stream 分别适合位统计、近似去重计数和消息流。

#### 78. 缓存穿透、击穿、雪崩是什么？

**回答：** 穿透是持续查询不存在的数据，可用参数校验、空值缓存、布隆过滤器；击穿是热点键失效瞬间大量请求打到数据库，可用互斥重建、逻辑过期；雪崩是大量键同时失效或缓存服务故障，可用过期时间加随机值、多级缓存、限流降级和高可用。

#### 79. 如何保证缓存与数据库一致性？

**回答：** 常见策略是先更新数据库，再删除缓存，并设置合理过期时间；并发要求更高时可用延迟双删、消息队列或订阅数据库变更日志。绝对实时一致成本很高，应先明确可接受的不一致窗口，并保证删除失败可重试。

#### 80. Redis 持久化 RDB 和 AOF 的区别？

**回答：** RDB 定期生成数据快照，文件紧凑、恢复快，但可能丢失最近一次快照后的数据；AOF 记录写命令，数据丢失窗口更小，但文件更大、恢复可能更慢。实际可组合使用，并结合复制和备份，持久化不等于高可用。

#### 81. 如何实现分布式锁？

**回答：** 基本要求是互斥、持有者解锁、自动过期和可容错。Redis 可用带随机唯一值的 `SET key value NX PX` 原子加锁，释放时用 Lua 校验持有者再删除；业务耗时不确定时还要续期。分布式锁不能替代数据库约束，强一致场景应评估共识系统或 fencing token。

#### 82. 为什么使用消息队列？

**回答：** 消息队列用于异步、解耦、削峰和事件驱动。例如下单后把通知、积分等非核心步骤异步化。代价是引入消息延迟、重复、丢失、顺序、积压和运维复杂度。

#### 83. 如何避免消息丢失？

**回答：** 生产端使用确认与重试，Broker 配置持久化和副本，消费端处理成功后再确认，并对失败消息重试或进入死信队列。业务还要有监控、对账和补偿；“至少一次”投递下必须处理重复。

#### 84. 如何处理重复消息？

**回答：** 消费者应设计为幂等，可使用业务唯一键、数据库唯一约束、去重表或状态机。不要只依赖短期 Redis 去重而忽略缓存丢失和过期后的重复。

#### 85. 如何保证消息顺序？

**回答：** 把需要有序的同一业务键路由到同一分区，并在单分区内串行消费。全局有序会显著限制吞吐，通常只保证订单、用户等局部有序。失败重试也要避免后续消息越过前序消息。

#### 86. CAP 定理是什么？

**回答：** 在发生网络分区时，分布式系统不能同时保证强一致性和可用性，只能根据业务选择倾向。CAP 中的 C 是线性一致性语境下的单一最新视图，A 是每个非故障节点都能在有限时间响应，P 是系统容忍网络分区。

#### 87. BASE 理论是什么？

**回答：** BASE 强调基本可用、软状态和最终一致性，是很多分布式业务对强一致性的工程折中。系统允许短暂不一致，通过重试、对账和补偿最终收敛，但必须明确收敛条件和异常处理。

#### 88. 什么是分布式事务？常见方案有哪些？

**回答：** 分布式事务协调跨服务或跨数据库的一组操作。常见方案有两阶段提交、TCC、Saga、事务消息和本地消息表。强一致方案协调成本高、可用性较低；业务常用最终一致方案，并通过幂等、重试、补偿和对账保证结果。

#### 89. 负载均衡有哪些算法？

**回答：** 常见算法有轮询、加权轮询、最少连接、随机、一致性哈希和基于延迟或负载的动态策略。四层负载均衡基于 IP 与端口，性能高；七层能理解 HTTP，支持按域名、路径、Header 路由，但处理成本更高。

#### 90. 什么是一致性哈希？

**回答：** 一致性哈希把节点和数据映射到哈希环，节点变化时只迁移相邻区间的数据，比普通取模减少大规模重映射。虚拟节点用于改善数据分布和负载均衡。

#### 91. 服务熔断、降级、限流的区别？

**回答：** 限流控制进入系统的请求量；熔断在下游持续失败时暂时停止调用，避免级联故障；降级是在资源不足或依赖异常时关闭非核心能力或返回兜底结果。三者通常与超时、重试、隔离一起构成稳定性策略。

#### 92. 重试为什么可能放大故障？

**回答：** 下游超载时立即重试会增加流量，形成重试风暴。应只对临时且幂等的错误重试，设置次数上限、指数退避、随机抖动和总超时预算，并避免多层同时重试。

#### 93. 微服务的优缺点是什么？

**回答：** 微服务按业务能力独立开发、部署和扩缩容，有利于团队自治和故障隔离；代价是网络调用、数据一致性、测试、观测、发布和运维复杂度显著上升。业务和团队规模不足时，结构清晰的模块化单体通常更合适。

### 4. 安全、质量与可观测性

#### 94. 认证和授权有什么区别？

**回答：** 认证回答“你是谁”，授权回答“你能做什么”。认证可基于密码、短信、证书或联合身份；授权常见 RBAC、ABAC。后端必须在每个受保护资源入口校验权限，不能只依赖前端隐藏按钮。

#### 95. Session 与 JWT 的区别？

**回答：** Session 通常把状态保存在服务端，客户端只持有会话 ID，便于主动失效但需要共享或粘性会话；JWT 把声明签名后交给客户端，便于跨服务验证，但吊销、续期和权限变更更复杂。JWT 默认只是签名，不是加密，敏感数据不能直接放入载荷。

#### 96. 密码应该如何保存？

**回答：** 绝不能明文或用可逆加密保存，应使用专门的慢哈希算法，如 Argon2、bcrypt 或 scrypt，并为每个密码使用随机盐。还应配合登录限速、多因素认证、泄漏密码检测和安全重置流程。

#### 97. 如何防止 SQL 注入？

**回答：** 核心是使用参数化查询或正确的 ORM 参数绑定，不把用户输入拼接到 SQL。动态表名、排序字段等不能参数化的部分要使用严格白名单。最小权限、日志审计和输入校验是补充防线。

#### 98. 单元测试、集成测试、端到端测试的区别？

**回答：** 单元测试验证小范围逻辑，速度快、定位准；集成测试验证模块与数据库、消息系统等协作；端到端测试验证完整用户流程，最接近真实但慢且维护成本高。测试结构应下层多、上层少，并覆盖关键失败路径。

#### 99. 日志、指标、链路追踪分别解决什么问题？

**回答：** 日志记录离散事件和上下文；指标用于聚合趋势、仪表盘和告警；链路追踪展示一次请求跨服务的调用路径与耗时。三者通过请求 ID、Trace ID 等关联，才能快速从告警定位到具体请求和日志。

#### 100. 如何设计一次线上故障排查？

**回答：** 先确认影响范围并止损，再依据指标判断是流量、应用、依赖还是资源问题；结合最近变更、日志、追踪、线程与数据库状态缩小范围；恢复后补充根因、时间线、修复项和防复发措施。排障中避免无依据地同时修改多个变量。

## 三、计算机网络核心知识

### 1. 网络分层与基础协议

#### 101. OSI 七层和 TCP/IP 模型分别是什么？

**回答：** OSI 七层从下到上是物理层、数据链路层、网络层、传输层、会话层、表示层、应用层。工程中常用 TCP/IP 四层：网络接口层、网际层、传输层、应用层。分层通过明确接口降低系统复杂度，但真实协议并不总严格对应单层。

#### 102. 数据在网络中如何封装？

**回答：** 应用数据向下经过传输层添加 TCP/UDP 首部，网络层添加 IP 首部，链路层添加帧头帧尾，再转成物理信号；接收端反向解封装。每层只处理本层协议并向上交付载荷。

#### 103. MAC 地址和 IP 地址的区别？

**回答：** MAC 地址主要用于同一链路内交付帧，IP 地址用于跨网络的逻辑寻址和路由。主机向远端 IP 发包时，链路层目标 MAC 通常是下一跳网关的 MAC，而不是远端主机的 MAC。

#### 104. ARP 的作用是什么？

**回答：** IPv4 中 ARP 用于在本地链路上根据 IP 地址查询对应 MAC 地址。主机先查 ARP 缓存，未命中时广播请求，目标返回应答。ARP 缺乏认证，可能受到欺骗攻击；IPv6 使用邻居发现协议承担类似功能。

#### 105. ICMP 有什么作用？

**回答：** ICMP 用于传递网络控制和错误信息，例如目标不可达、超时、重定向。`ping` 通常使用 Echo Request/Reply，`traceroute` 利用 TTL 逐跳过期响应发现路径。屏蔽 ICMP 不等于更安全，可能影响路径 MTU 发现和排障。

#### 106. 子网掩码和 CIDR 是什么？

**回答：** 子网掩码把 IP 分成网络位和主机位，CIDR 用 `/前缀长度` 表示网络位数量，例如 `/24`。判断两台主机是否同网段，就是把 IP 与掩码按位与后比较网络号。

#### 107. 路由器如何选择下一跳？

**回答：** 路由器查路由表，优先匹配前缀最长的路由，再根据管理距离、度量值等选择可用路径，最后把包转发到下一跳或出接口。没有更具体路由时可能使用默认路由。

#### 108. NAT 的作用和代价是什么？

**回答：** NAT 在内外网地址之间转换，常通过端口复用让多个私网主机共享公网地址，缓解 IPv4 地址不足。代价是破坏端到端连接，增加状态维护，使入站连接、P2P 和某些协议更复杂。

#### 109. DHCP 的基本流程是什么？

**回答：** 典型流程是客户端广播 Discover，服务器返回 Offer，客户端发送 Request，服务器回复 ACK，即 DORA。服务器下发 IP、掩码、网关、DNS 和租期等配置。

#### 110. DNS 查询过程是什么？

**回答：** 客户端先查浏览器、系统和本地缓存，再向递归解析器查询；解析器未命中时依次向根、顶级域和权威 DNS 获取结果并缓存。DNS 常用 UDP 53，响应过大、区域传送等场景也会使用 TCP，现代还支持 DoH 和 DoT。

#### 111. DNS 中常见记录类型有哪些？

**回答：** `A` 映射 IPv4，`AAAA` 映射 IPv6，`CNAME` 设置别名，`MX` 指定邮件服务器，`TXT` 存文本验证或策略，`NS` 指定权威服务器。TTL 决定缓存时间，也影响变更生效速度与查询压力。

### 2. TCP、UDP 与可靠传输

#### 112. TCP 和 UDP 的区别？

**回答：** TCP 面向连接，提供可靠、有序、字节流传输，并实现流量与拥塞控制；UDP 无连接，尽力交付，以数据报为单位，首部小、时延低。实时音视频、DNS、QUIC 常基于 UDP，但应用可在其上自行实现可靠性。

#### 113. TCP 为什么需要三次握手？

**回答：** 三次握手用于确认双方收发能力、同步初始序列号并协商参数。两次不足以让服务端确认客户端已收到自己的序列号，也更难避免旧连接请求造成资源误分配。

#### 114. TCP 三次握手过程是什么？

**回答：** 客户端发送 `SYN` 和初始序列号；服务端返回 `SYN+ACK`，确认客户端序列号并提供自己的序列号；客户端再发送 `ACK`。之后双方进入已建立状态。

#### 115. TCP 为什么通常四次挥手？

**回答：** TCP 是全双工，关闭两个方向要分别发送 FIN 和确认。收到对方 FIN 只表示对方不再发送，自己可能仍有数据，所以 ACK 与自己的 FIN 常分开发送；如果能同时关闭，也可能合并部分报文。

#### 116. TIME_WAIT 为什么存在？

**回答：** 主动关闭方进入 TIME_WAIT，主要为了确保最后一个 ACK 丢失时还能重发，并让旧连接的延迟报文在网络中消失，避免污染相同四元组的新连接。持续时间通常与最大报文生存时间有关。

#### 117. TCP 如何保证可靠性？

**回答：** TCP 通过序列号、确认应答、校验和、超时重传、快速重传、滑动窗口和有序重组实现可靠传输。可靠不代表永不失败，而是在连接有效时尽力检测丢失、重复、乱序并恢复，最终失败会通知应用。

#### 118. 滑动窗口解决什么问题？

**回答：** 滑动窗口允许发送方在未收到逐个确认前连续发送多个字节，提高带宽利用率。接收窗口用于流量控制，避免压垮接收方；实际发送量还受拥塞窗口限制。

#### 119. 流量控制和拥塞控制的区别？

**回答：** 流量控制保护接收端，根据接收窗口限制发送速率；拥塞控制保护整个网络，根据丢包、时延等信号调整拥塞窗口。实际可发送窗口通常取接收窗口和拥塞窗口的较小值。

#### 120. TCP 拥塞控制有哪些核心机制？

**回答：** 经典机制包括慢启动、拥塞避免、快速重传和快速恢复。连接先快速增大拥塞窗口，接近阈值后线性增长；检测到拥塞则降低窗口。现代系统还可能使用 CUBIC、BBR 等不同算法。

#### 121. 粘包和拆包是什么？

**回答：** TCP 是字节流，没有应用消息边界，一次发送的数据可能被合并或拆分读取。应用层要自己定义边界，常用固定长度、分隔符、长度字段或自描述协议。UDP 保留数据报边界，没有 TCP 意义上的粘包。

#### 122. 什么是半连接队列和全连接队列？

**回答：** 服务端收到 SYN 后，未完成三次握手的连接进入半连接队列；握手完成、尚未被应用 `accept` 的连接进入全连接队列。队列溢出、应用处理慢或 SYN 攻击都可能导致连接失败。

### 3. HTTP、HTTPS 与实时通信

#### 123. HTTP 是无状态协议是什么意思？

**回答：** 每个 HTTP 请求在协议语义上独立，服务器不会自动记住前一个请求的业务状态。登录状态通常通过 Cookie、Session、Token 等机制额外维护。无状态有利于横向扩展，但业务状态仍需要存储。

#### 124. 常见 HTTP 状态码有哪些？

**回答：** `200` 成功，`201` 创建成功，`204` 成功但无正文，`301/308` 永久重定向，`302/307` 临时重定向，`304` 缓存未修改，`400` 请求错误，`401` 未认证，`403` 已认证但无权限，`404` 不存在，`409` 冲突，`429` 限流，`500` 服务端错误，`502/504` 网关异常。

#### 125. HTTP/1.1、HTTP/2、HTTP/3 的主要区别？

**回答：** HTTP/1.1 支持持久连接，但同一连接上响应顺序会造成队头阻塞，浏览器常开多个连接；HTTP/2 使用二进制分帧和多路复用，并支持头部压缩，但底层 TCP 丢包仍会阻塞同连接流；HTTP/3 基于 QUIC/UDP，让不同流更独立，并减少连接与 TLS 建立时延。

#### 126. HTTP Keep-Alive 有什么作用？

**回答：** 它让多个 HTTP 请求复用同一传输连接，减少 TCP 和 TLS 握手开销、降低延迟。HTTP/1.1 默认使用持久连接，但服务端仍需设置合理的空闲超时和最大请求数，避免连接长期占用资源。

#### 127. HTTPS 如何保证安全？

**回答：** HTTPS 是 HTTP 运行在 TLS 之上。TLS 通过证书链验证服务器身份，使用非对称密码协商密钥，再用对称加密保护数据机密性，并用认证机制保证完整性。它不能防止终端被入侵、业务漏洞或用户主动信任恶意证书。

#### 128. TLS 握手大致做了什么？

**回答：** 客户端发送支持的版本、算法和随机参数；服务端选择参数并发送证书和密钥交换信息；客户端验证证书，双方基于密钥交换计算会话密钥，确认握手完整后开始加密通信。TLS 1.3 简化了流程，并支持更快的会话恢复。

#### 129. 数字证书和 CA 的作用是什么？

**回答：** 证书把域名身份与公钥绑定，并由受信任 CA 签名。客户端验证证书域名、有效期、签名链和吊销状态，从系统信任根逐级建立信任。证书证明的是公钥归属，不是网站业务绝对可信。

#### 130. 对称加密和非对称加密如何配合？

**回答：** 对称加密速度快，适合大量数据；非对称密码便于身份认证和密钥交换，但计算成本高。TLS 通常用证书与非对称机制完成认证和密钥协商，再用生成的对称会话密钥传输数据。

#### 131. HTTP 长轮询、SSE、WebSocket 如何选择？

**回答：** 长轮询兼容性好但请求开销较大；SSE 基于 HTTP，由服务器单向持续推送文本，适合通知和进度；WebSocket 建立后提供双向全双工通信，适合聊天、协作和实时游戏。选择时看通信方向、数据类型、连接规模和代理支持。

#### 132. WebSocket 如何建立连接？

**回答：** 客户端先发送带 `Upgrade: websocket` 的 HTTP 请求，服务端同意后返回 `101 Switching Protocols`，之后在同一连接上使用 WebSocket 帧双向传输。生产中仍要处理鉴权、心跳、重连、背压和连接扩容。

### 4. 网络工程与排障

#### 133. 正向代理和反向代理的区别？

**回答：** 正向代理代表客户端访问外部服务，外部服务通常不知道真实客户端；反向代理代表后端服务器接收客户端请求，客户端通常不知道具体后端。Nginx 常作为反向代理，承担 TLS 终止、路由、缓存和负载均衡。

#### 134. CDN 的工作原理是什么？

**回答：** CDN 把内容缓存到靠近用户的边缘节点，DNS 或调度系统把用户引导到合适节点；未命中时边缘节点向源站回源。它可降低时延和源站压力，但要处理缓存键、失效刷新、回源保护和动态内容策略。

#### 135. 什么是队头阻塞？

**回答：** 队头阻塞指队列前面的任务延迟导致后续任务无法推进。HTTP/1.1 流水线存在应用层队头阻塞；HTTP/2 解决了 HTTP 层多路复用问题，但 TCP 丢包仍会影响同连接所有流；HTTP/3 通过 QUIC 流减少这一影响。

#### 136. MTU 和 MSS 是什么？

**回答：** MTU 是链路层一次可承载的最大网络层包大小，以太网常见 1500 字节；MSS 是 TCP 报文段中应用数据的最大长度，通常约等于 MTU 减去 IP 和 TCP 首部。设置不当可能导致分片、丢包或访问某些站点卡住。

#### 137. `ping` 通但端口不通，可能是什么原因？

**回答：** ICMP 可达只说明基础路径可能正常。端口不通可能是服务未监听、监听在错误地址、防火墙或安全组拦截、路由或 NAT 配置错误、代理配置异常、连接队列满或应用已失去响应。应逐层检查 DNS、路由、端口监听、握手和应用日志。

#### 138. 如何排查网站访问慢？

**回答：** 先拆分 DNS、建连、TLS、首字节、下载、渲染各阶段耗时；再检查客户端网络、CDN、网关、服务、数据库和第三方依赖。使用浏览器网络面板、`curl` 时间指标、日志、指标和链路追踪定位，避免只看总耗时。

#### 139. `502`、`503`、`504` 常见原因是什么？

**回答：** `502` 通常表示网关收到上游无效响应或连接失败；`503` 表示服务暂不可用，可能过载、维护或无健康实例；`504` 表示网关等待上游超时。排查要结合反向代理日志、上游健康、超时配置、连接池和依赖耗时。

#### 140. 如果出现大量连接，服务端应检查什么？

**回答：** 检查连接状态分布、文件描述符上限、监听与 accept 队列、端口范围、Keep-Alive、线程或协程数量、内存、负载均衡和异常客户端。大量 `TIME_WAIT` 与大量 `CLOSE_WAIT` 含义不同：前者常与主动关闭和短连接有关，后者通常提示应用未及时关闭收到 FIN 的连接。

## 四、高频综合场景题

#### 141. 如何设计一个高并发秒杀系统？

**回答：** 核心是把无效流量挡在前面，并保证库存不超卖。静态资源走 CDN；网关做鉴权、限流和防刷；库存预热到缓存并原子扣减；请求进入消息队列削峰；消费者幂等创建订单；数据库用唯一约束或条件更新兜底；最后通过对账和补偿处理异常。还要设计活动预热、热点隔离、降级和监控。

#### 142. 如何避免超卖？

**回答：** 单库可使用带库存条件的原子更新，例如库存大于零才扣减，并检查受影响行数；也可用悲观锁或乐观锁。高并发时可在 Redis 中原子预扣，再异步落库，但必须配合订单超时回补、幂等、对账和数据库最终约束。

#### 143. 如何设计登录系统？

**回答：** 密码使用慢哈希加盐保存；登录接口做 TLS、限速、验证码或多因素认证；认证成功后签发安全会话，Cookie 设置 `HttpOnly`、`Secure`、合适的 `SameSite`；敏感操作再次校验；支持过期、刷新、退出和主动吊销；全链路日志脱敏并监控异常登录。

#### 144. 如何实现大文件上传？

**回答：** 前端切片并计算文件标识，可并发上传、失败重试和断点续传；后端校验分片、幂等保存并在完成后合并，最终校验大小与哈希。生产中常让客户端通过临时凭证直传对象存储，后端只负责权限和元数据，避免应用服务器成为带宽瓶颈。

#### 145. 如何设计接口防重复提交？

**回答：** 客户端按钮禁用只能改善体验，真正保证要在服务端。服务端接收幂等键，将其与业务主体绑定，并原子记录处理状态和结果；重复请求返回相同结果。数据库唯一约束或状态机是最终兜底。

#### 146. 前端请求偶发重复，如何排查？

**回答：** 先在浏览器网络面板确认请求数量和触发栈，再检查事件重复绑定、组件重复挂载、Effect 依赖、开发模式检查、自动重试、表单默认提交、代理重试和用户连击。后端仍要保证关键接口幂等，不能假设客户端永不重复。

#### 147. 页面白屏如何排查？

**回答：** 先看 HTML 是否返回、静态资源是否成功、控制台是否有语法或运行时错误，再检查路由基路径、资源 public path、浏览器兼容、CSP、接口阻塞和部署版本。应准备错误边界、资源失败监控、版本回滚和基础兜底页。

#### 148. 接口变慢如何定位？

**回答：** 从入口延迟分位数和 Trace 开始，把耗时分解为排队、应用计算、数据库、缓存、RPC 和外部依赖；同时看 CPU、内存、GC、线程池、连接池和锁。用同一请求 ID 关联日志，先止损，再通过压测或性能剖析验证根因。

#### 149. 如何设计短链接系统？

**回答：** 生成唯一短码并映射到长 URL，读路径用缓存加速，未命中查数据库；短码可由全局 ID 转 Base62、随机码加唯一约束等方式生成。还要考虑过期、恶意链接检测、热点缓存、访问统计、重定向状态码和防枚举。

#### 150. 如何回答“你遇到过最难的线上问题”？

**回答模板：** 用 STAR 结构：背景和影响范围；你的明确任务；你如何用指标、日志、链路和实验缩小问题；最终根因、止损和修复；事后增加了什么监控、测试或机制。重点体现证据链、取舍、协作和防复发，不要只说“重启解决”。

## 五、最后冲刺：30 句必背结论

1. `defer` 并行下载、解析后按顺序执行；`async` 下载完立即执行、顺序不确定。
2. BFC 是独立布局上下文，可包含浮动并避免部分外边距折叠。
3. 闭包是函数和声明时词法环境的组合。
4. 箭头函数没有自己的 `this`，它捕获外层 `this`。
5. Event Loop 每轮先执行一个宏任务，再清空微任务，然后浏览器择机渲染。
6. 防抖等停止后执行，节流限制单位时间的执行次数。
7. 虚拟 DOM 的主要价值是声明式 UI 和跨平台抽象，不保证永远更快。
8. 列表 `key` 必须稳定、唯一，尽量不用数组下标。
9. 性能优化先测量，重点看 LCP、INP、CLS 和真实用户数据。
10. XSS 靠上下文转义、内容清洗和 CSP；CSRF 靠 SameSite、Token 和来源校验。
11. 幂等指重复执行后的最终业务效果一致。
12. 并发是任务交替推进，并行是任务同时执行。
13. 死锁四条件：互斥、请求并保持、不可剥夺、循环等待。
14. B+ 树树高低、范围查询友好，适合磁盘索引。
15. 联合索引按定义顺序排序，是否命中必须看执行计划。
16. ACID 是原子性、一致性、隔离性、持久性。
17. MVCC 用多版本和可见性规则减少读写冲突，但不等于完全无锁。
18. 缓存更新常用“更新数据库，再删除缓存”，并处理删除失败。
19. 穿透查不存在，击穿打热点键，雪崩是大量键或缓存整体失效。
20. 消息系统通常按至少一次投递设计，消费者必须幂等。
21. CAP 讨论的是发生网络分区时一致性与可用性的取舍。
22. 限流控入口，熔断停故障依赖，降级保核心功能。
23. 认证确认身份，授权确认权限。
24. TCP 可靠、有序、面向连接；UDP 无连接、按数据报尽力交付。
25. 三次握手用于确认双方收发能力并同步序列号。
26. TIME_WAIT 确保最后 ACK 可重传，并让旧报文自然消失。
27. 流量控制保护接收端，拥塞控制保护网络。
28. HTTP/2 多路复用仍受 TCP 层丢包影响；HTTP/3 基于 QUIC。
29. HTTPS 通过证书认证身份，通过密钥协商和对称加密保护传输。
30. 排障先确认范围和止损，再用指标、日志、追踪构建证据链。
